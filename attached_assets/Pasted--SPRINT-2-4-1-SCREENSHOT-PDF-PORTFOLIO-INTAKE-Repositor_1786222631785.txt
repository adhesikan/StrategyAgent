============================================================
2. OBJECTIVE
============================================================

Allow an authenticated user to create/import a portfolio from:

A. Screenshot / image
B. PDF brokerage statement

Examples:

- screenshot from Fidelity
- screenshot from Schwab
- screenshot from Robinhood
- screenshot from TradeStation
- screenshot from Interactive Brokers
- mobile portfolio screenshot
- brokerage account statement PDF

The system should extract candidate positions, normalize them, show a preview,
allow correction, and only then persist them.

Workflow:

Upload
→ Extract
→ Normalize
→ Validate
→ Preview
→ User Corrects
→ Confirm
→ Canonical PortfolioPosition rows

No database write before confirmation.

============================================================
5. IMAGE EXTRACTION STRATEGY
============================================================

Use the existing AI/vision capability available in the application if present.

AI is allowed HERE because this is unstructured data extraction.

AI is NOT allowed to determine:

portfolio quality
investment rating
buy/sell decisions
position sizing
recommendations

Use AI only to transform:

unstructured image
→ structured candidate rows

Request strict structured JSON.

Example:

{
  "positions": [
    {
      "symbol": "NVDA",
      "quantity": 100,
      "averageCost": 132.50,
      "costBasis": 13250,
      "marketValue": 18000,
      "confidence": 0.98
    }
  ],
  "warnings": []
}

Never trust the AI extraction directly.

Pass results through deterministic normalization and validation.

============================================================
7. PDF IMPORT
============================================================

Create:

POST /api/portfolio/import/pdf

Authenticated user only.

Support normal brokerage statement PDFs.

Preferred extraction sequence:

1. Parse embedded PDF text when available.
2. Identify portfolio/holdings table.
3. Extract candidate holdings.
4. If PDF has no usable text and current architecture supports safe visual-page
   processing, process only necessary pages.
5. Normalize.
6. Preview.

Do not blindly send an entire large PDF to an AI model.

============================================================
8. PDF SAFETY
============================================================

Requirements:

PDF only
max file size — choose sensible limit, e.g. 15 MB
max page count
no embedded JavaScript execution
no attachment execution
no macro/script execution
no arbitrary path writes
temporary content cleaned up
no public object URLs
no portfolio statement retained unnecessarily

If original uploaded files are not needed after extraction:

do not permanently store them.

Document actual retention behavior.
