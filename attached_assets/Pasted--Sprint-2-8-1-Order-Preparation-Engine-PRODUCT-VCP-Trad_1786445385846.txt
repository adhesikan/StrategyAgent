======================================================================
CORE ARCHITECTURE CONTRACT
======================================================================

The execution pipeline is:

Saved Trade Plan
        ↓
Current Lifecycle Validation
        ↓
Execution Preflight
        ↓
Order Preparation
        ↓
Future Equity / Options Order Preview
        ↓
Future Final Validation
        ↓
Future Explicit Confirmation
        ↓
Future Broker Submission

Sprint 2.8.1 implements ONLY:

ORDER PREPARATION.

It transforms approved INPUT DATA from a PASSING CURRENT PREFLIGHT into a
structured NON-EXECUTABLE ORDER DRAFT.

It MUST NOT:

submit an order

place an order

replace an order

cancel an order

call a broker order endpoint

create an executable broker payload

======================================================================
PERMANENT EXECUTION RULE
======================================================================

Order Preparation may describe what a future broker order COULD contain.

Order Preparation is NOT:

broker authorization

user confirmation

order submission

execution

fill

position creation

The existence of an OrderDraft must never cause broker mutation.

OBJECTIVE
======================================================================

Build a canonical Order Preparation Engine that takes:

User-owned Saved Trade Plan
+
Current PASSING ExecutionPreflightResult
+
Selected Broker Account
+
Selected Structure
+
Current authoritative quote/reference data
+
User-selected order preferences
        ↓
Canonical OrderDraft
        ↓
Future 2.8.2 / 2.8.3 Preview

The engine should answer:

"If this research plan were later converted into a broker order, what
would the structured order draft contain?"

It must NOT answer:

"Submit this trade."

======================================================================

OrderDraft

======================================================================

114. PERMANENT ARCHITECTURE INVARIANT
======================================================================

Document permanently:

An OrderDraft is a non-executable representation of a possible future
broker order.

It must remain cryptographically/logically bound to:

the authenticated user

a saved Trade Plan version

a current Execution Preflight

an authorized broker account

the user-selected structure

the user-selected quantity/preferences

and a freshness window.

It may NEVER itself authorize or trigger broker submission.

Only a later server-side execution flow with fresh validation,
short-lived explicit confirmation, persistent idempotency, and enabled
execution policy may transform an OrderDraft into a broker submission.
