======================================================================
PERMANENT ARCHITECTURE PRINCIPLE
======================================================================

Equity Order Preview is a user-review surface.

It displays the exact current non-executable OrderDraft and its supporting
validation context.

It may not silently:

change quantity

change account

change side intent

change broad expression type

change Trade Plan

change order type

change time in force

change limit reference

or infer a different trade.

Any user change must route back through explicit draft editing and
revalidation.

OBJECTIVE
======================================================================

Build a canonical Equity Order Preview experience that takes:

User-owned saved Trade Plan
+
selectedBy USER broad expression = STOCK
+
current PASSING Execution Preflight
+
current VALID non-executable OrderDraft
+
authoritative current quote context
+
risk/planning context
        ↓
EquityOrderPreview

The preview should answer:

"What exactly does my current equity order draft represent?"

"What account would it use later?"

"What quantity did I select?"

"What kind of order did I draft?"

"What price reference is being shown?"

"What estimated notional does that imply?"

"What risks, warnings, freshness limits, and blockers apply?"

It must NOT answer:

"Should I submit this order?"

non-executable equity OrderDraft.

current market context

estimated notional

freshness

warnings

blockers

change the user's STOCK expression selection

change quantity

change account

change side intent

change order type

change TIF

change limit price

submit an order

or serve as user confirmation.

All changes must return through Order Preparation and create/revalidate the
