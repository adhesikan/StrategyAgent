ROOT ISSUE

Global checkFreshness() uses:

SCAN_STALE_WEEKDAYS = 3

Therefore:

Friday Aug 14 bar
→ Monday Aug 17 after market close
→ weekdayDistance = 1
→ freshness = "fresh"

This prevents Phase 3 external refresh from running.

Production already confirmed exactly this:

AMD:
  asOf: 2026-08-14
  freshness: "fresh"

MU:
  asOf: 2026-08-14
  freshness: "fresh"

even after the Aug 17 regular session completed.

The AI Infrastructure Watch is specifically labeled "Latest daily close",
so its freshness requirement must be stricter than the Opportunity Engine's
multi-day scanner tolerance.

============================================================
IMPORTANT ARCHITECTURE RULE
============================================================

DO NOT change the global:

SCAN_STALE_WEEKDAYS = 3

policy.

That policy is used by scanning/research infrastructure and may intentionally

Instead introduce/reuse a DAILY_CLOSE_CURRENTNESS policy specifically for
user-facing latest-close surfaces.

============================================================
DESIRED SEMANTICS
============================================================

For AI Infrastructure Watch:

The stored bar is current ONLY if it represents the latest completed U.S.
trading session, subject to a short post-close ingestion grace period.

Examples:

FRIDAY AFTER CLOSE:
Friday bar = current

SATURDAY:
Friday bar = current

SUNDAY:
Friday bar = current

MONDAY BEFORE MARKET OPEN:
Friday bar = current

MONDAY DURING REGULAR SESSION:
Friday bar may remain the latest completed DAILY bar

MONDAY AFTER REGULAR CLOSE + ingestion grace period:
Monday bar expected

If latest stored bar is still Friday:
→ attempt external refresh

If refresh succeeds:
→ persist Monday bar
→ display Monday close
→ Latest daily close

If refresh fails:
→ last = null
→ freshness = stale
→ display "—"

Never continue displaying Friday's price as a current Monday daily close after
the Monday session has completed and the grace period has expired.
