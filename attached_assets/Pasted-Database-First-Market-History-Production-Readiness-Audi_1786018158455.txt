Database-First Market History — Production Readiness Audit

PRIMARY REPOSITORY

VCP Trader AI / StrategyAgent

CURRENT IMPLEMENTATION

The database-first historical market-data architecture is now implemented.

Key behavior:

- global deterministic scans use PostgreSQL historical bars
- scan-time external history fetching is disabled
- canonical market-history service owns provider selection
- external refresh requires:
  allowExternalRefresh = true
  and MARKET_HISTORY_EXTERNAL_REFRESH_ENABLED = true
- emergency rollback:
  MARKET_HISTORY_DATABASE_FIRST = false
- internal MCP history route is backward-compatible
- provider error classification is improved
- supported brokers are capability-based
- 62 new tests were added
- 1,414 server tests pass

GOAL

Verify that the production historical-bar database and ingestion pipeline are ready to support the Opportunity Engine before deployment.

5. DEFINE THE PRODUCTION READINESS THRESHOLD
==================================================

Recommend and enforce a clear threshold before enabling database-first scanning.

Suggested initial rule:

GO:
- at least 95% of the universe is READY or STALE_BUT_USABLE
- all required market-regime symbols are READY
- no invalid-bar integrity failures
- missing symbols are explicitly accounted for as unavailable

CONDITIONAL_GO:
- 85–94.99% coverage
- missing symbols are non-critical
- previous valid opportunity snapshot exists
- ingestion/backfill is actively filling gaps

NO_GO:
- below 85% coverage
- required index/regime symbols missing
- widespread invalid bars
- ingestion not functioning

Document the final selected threshold.
