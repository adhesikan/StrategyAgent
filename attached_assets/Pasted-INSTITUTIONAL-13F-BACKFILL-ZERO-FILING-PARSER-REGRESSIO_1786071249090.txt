3. FIND WHY totalFilings IS ZERO
====================================================================

Trace the full call path:

run-institutional-backfill.ts
→ runInstitutionalIngestion()
→ quarter downloader
→ ZIP extraction
→ submission parser
→ information-table parser
→ filing persistence
→ aggregation

Identify exactly where the count changes to zero.

Investigate these likely defects:

A. ZIP entry-name mismatch
- parser expects old or incorrect filenames;
- filenames are uppercase;
- filenames include a directory prefix;
- extension changed.

B. Incorrect content parser
- parsing TSV as CSV;
- parsing a ZIP as text;
- treating the bulk dataset as EDGAR JSON;
- incorrect encoding or BOM handling.

C. Header mismatch
- parser expects camelCase or historical columns;
- SEC fields are uppercase or renamed;
- required-column validation rejects every row.

D. Quarter mismatch
- dataset quarter label and period-of-report date are compared incorrectly;
- code expects 2026-Q1 but records use 2026Q1 or 2026-03-31;
- fiscal/calendar interpretation is wrong.

E. Join-key mismatch
- SUBMISSION and INFOTABLE are joined using the wrong accession-number field;
- accession formatting differs because hyphens or leading zeroes were removed.

F. Silent error swallowing
- row-level parser catches errors and returns [];
- validation failures are counted neither as rejected nor failed;
- missing required files produce an empty array instead of an error.

Return the exact root cause—not only a workaround.

====================================================================
4. EMPTY-QUARTER POLICY
====================================================================

A downloaded quarter containing zero parsed filings must not be reported as success.

Introduce explicit result states:

- SUCCESS
- PARTIAL_SUCCESS
- EMPTY_NOT_PUBLISHED
- EMPTY_PARSE_FAILURE
- FAILED

Rules:

EMPTY_NOT_PUBLISHED:
- official quarterly dataset is unavailable or not yet published;
- response is 404 or page/archive indicates no quarter dataset;
- no ingestion-run success;
- no aggregates generated;
- safe retry later.

EMPTY_PARSE_FAILURE:
- a nontrivial archive downloaded;
- expected source files exist;
- parser returns zero filings or holdings;
- mark ingestion run FAILED;
- emit safe diagnostics;
- exit CLI non-zero.

SUCCESS requires at minimum:

- filingCount > 0
- holdingCount > 0

unless an explicitly supported dataset genuinely contains no eligible holdings,
which must be independently classified.

Do not create an aggregate-completed event with symbolCount: 0 and call it success.
