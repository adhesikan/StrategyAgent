2. IMPLEMENT A ROBUST ENTRY RESOLVER
====================================================================

Replace quarter-prefix assumptions with a general-purpose ZIP entry resolver.

Create a pure helper similar to:

resolveRequiredArchiveEntry(
  entries,
  requiredBaseName
): ZipEntry | null

Required behavior:

1. Match entry names case-insensitively.
2. Normalize path separators.
3. Compare using the basename of each ZIP entry.
4. Prefer an exact bare basename match:
   SUBMISSION.tsv
   INFOTABLE.tsv
5. Support legacy prefixed names:
   2023Q4_SUBMISSION.tsv
   2023Q4_INFOTABLE.tsv
6. Support nested paths:
   some-folder/SUBMISSION.tsv
7. Support case variants:
   SUBMISSION.TSV
   submission.tsv
   Submission.tsv
8. Reject unrelated partial matches such as:
   OLD_SUBMISSION_BACKUP.tsv
   SUBMISSION_NOTES.txt
9. Detect ambiguity:
   if multiple equally valid entries match, fail safely with
   AMBIGUOUS_ARCHIVE_ENTRY rather than selecting arbitrarily.

Preferred lookup order:

A. Exact bare basename match, case-insensitive
B. Exact recognized legacy-prefixed basename match
C. Unique nested basename match
D. Failure or ambiguity

Do not depend on the descriptor quarter to find post-2023 bare filenames.
