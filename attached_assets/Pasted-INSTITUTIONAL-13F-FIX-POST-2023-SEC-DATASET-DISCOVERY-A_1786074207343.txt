INSTITUTIONAL 13F — FIX POST-2023 SEC DATASET DISCOVERY AND PERIOD MAPPING

Repository:
VCP Trader AI / StrategyAgent

CURRENT PRODUCTION OBSERVATION

Command:

npx tsx scripts/run-institutional-backfill.ts --quarters 2 --dry-run

reported every dataset from 2024Q1 through 2026Q3 as “not yet published” and selected
only 2023Q4.

This is incorrect.

The official SEC Form 13F Data Sets page currently lists post-2023 downloads using
three-month date-range filenames rather than YYYYqN filenames.

Examples verified from the official SEC page:

01mar2026-31may2026_form13f.zip
01dec2025-28feb2026_form13f.zip
01sep2025-30nov2025_form13f.zip
01jun2025-31aug2025_form13f.zip
01mar2025-31may2025_form13f.zip

Older datasets continue to use names such as:

2023q4_form13f.zip

The availability probe currently appears to construct:

YYYYqN_form13f.zip

for all years, causing valid post-2023 datasets to return HTTP 404 and be mislabeled
as unpublished.

This is a focused dataset-discovery and reporting-period mapping fix.

- TSV parsing
- database schema
- amendment handling
- aggregation formulas
- mapping policy
- UI

2. USE THE OFFICIAL SEC DATASET INDEX AS SOURCE OF TRUTH
====================================================================

Preferred implementation:

Fetch and parse the official human-readable dataset index:

https://www.sec.gov/data-research/sec-markets-data/form-13f-data-sets

Extract the official ZIP links from that page.

Do not guess publication availability solely from constructed URLs.

Build a normalized dataset catalog from official links.

Suggested normalized type:

InstitutionalDatasetCatalogEntry {
  downloadUrl: string;
  fileName: string;
  displayLabel: string;
  windowStart: string;
  windowEnd: string;
  publicationModel: "legacy_quarter" | "three_month_window";
  canonicalPeriodLabel: string;
  expectedPeriodOfReport: string;
}

Requirements:

- only accept HTTPS links hosted on sec.gov;
- only accept filenames ending in _form13f.zip;
- reject arbitrary/external URLs;
- use SEC_USER_AGENT;
- bounded request rate;
- cache the catalog;
- do not fetch the catalog on ordinary user page requests;
- safe retry/backoff;
- no HTML scraping outside the official SEC dataset page.

If parsing the official index is unsuitable, implement a documented deterministic
filename mapping based on the SEC’s published convention—but index parsing is
preferred because it remains resilient to future naming changes.

====================================================================
3. SUPPORT BOTH NAMING CONVENTIONS
====================================================================

Legacy convention:

2013Q2 through 2023Q4, where available:

YYYYqN_form13f.zip

Post-2023 convention:

three-month window filenames, including:

01marYYYY-31mayYYYY_form13f.zip
01junYYYY-31augYYYY_form13f.zip
01sepYYYY-30novYYYY_form13f.zip
01decYYYY-28febYYYY+1_form13f.zip

Handle leap-year February correctly when constructing or validating filenames:

28feb or 29feb as applicable.

Do not assume all future filenames follow exactly the same day strings when the
official index supplies the actual URL.

====================================================================
4. CORRECT PERIOD SEMANTICS
====================================================================

The SEC datasets now group filings by filing-submission window, not by the holdings
quarter in the filename.

For example:

01mar2026-31may2026_form13f.zip

primarily contains filings submitted during March–May 2026, many of which report
holdings as of:

2026-03-31

The application must distinguish:

A. SEC dataset window

Example:
2026 March–May dataset

B. Holdings period of report

Example:
2026-03-31 / 2026Q1

Do not label the dataset window itself as the holdings quarter without inspecting
SUBMISSION.TSV period-of-report fields.

During ingestion:

- parse every filing’s actual CONFORMED-PERIOD-OF-REPORT;
- persist the real period-of-report;
- aggregate by actual period-of-report;
- do not force every row in one ZIP into a single assumed quarter;
- allow amendments or late filings with a different report period;
- record the source dataset filename/window separately.

====================================================================
5. REDEFINE --quarters N
====================================================================

The user/operator meaning of:

--quarters 2

should be:

Ingest enough published SEC bulk datasets to obtain the two most recent distinct
13F holdings periods of report.

It should not simply mean:

Download two ZIP files.

Preferred workflow:

1. Load published dataset catalog.
2. Select newest dataset windows.
3. Inspect or ingest them newest-first.
4. Determine distinct period-of-report dates represented.
5. Continue backward until at least N recent comparable holdings quarters are covered.
6. Print the selected dataset windows and expected holdings periods clearly.

Dry-run example:

Published dataset windows selected:
- Mar 1–May 31, 2026
  Expected primary holdings period: 2026-03-31
- Dec 1, 2025–Feb 28, 2026
  Expected primary holdings period: 2025-12-31

Target holdings quarters:
- 2026Q1
- 2025Q4

Do not print:

2026Q2 unpublished

when the actual question is whether the March–May publication window exists.
