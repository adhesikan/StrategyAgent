Implement Recommendation Engine Transparency (Explainability) for VCP Trader.

IMPORTANT

Do NOT modify the recommendation algorithm.

Do NOT modify scanner algorithms.

Do NOT modify ranking.

Do NOT change recommendation decisions.

Do NOT change MCP.

Only expose the deterministic evidence already produced by the recommendation engine.

Everything must remain additive.

No breaking API changes.

Wait for review before committing.

----------------------------------------------------
GOAL
----------------------------------------------------

When a recommendation request returns:

LIVE_OPTIONS
ESTIMATED_OPTIONS
STOCK
WATCH
NO_TRADE
UNSUPPORTED

the user should understand WHY.

Instead of:

"No Trade"

the user should see:

• how many strategies were evaluated
• which strategies passed
• which strategies failed
• why they failed
• what would need to happen to become actionable
• how confident the engine is in its decision

This is NOT chain-of-thought.

It is deterministic recommendation evidence.

----------------------------------------------------
1. Recommendation Evidence Model
----------------------------------------------------

Extend the structured recommendation response with:

recommendationEvidence

Example:

{
  "summary": {
      "strategiesEvaluated": 12,
      "actionable": 0,
      "watch": 2,
      "rejected": 10,
      "dataQuality":"LIVE"
  },

  "evaluations":[
      {
          "strategy":"Momentum Breakout",
          "status":"REJECTED",
          "reason":"Entry trigger not reached"
      },
      {
          "strategy":"Trend Continuation",
          "status":"WATCH",
          "reason":"Needs another higher low"
      }
  ],

  "watchConditions":[
      {
          "condition":"Close above $214.85"
      },
      {
          "condition":"Volume > 1.5x average"
      }
  ],

  "decisionFactors":[
      "No strategy produced a qualifying reward/risk",
      "Entry trigger missing",
      "Upcoming earnings"
  ]
}

Everything must come from deterministic engine data.

Never fabricate.

5. Recommendation Confidence
----------------------------------------------------

NO_TRADE

Low Confidence.

Instead compute:

Recommendation Confidence

evaluation completeness

strategy coverage

data quality

live vs simulated

missing data

provider health

HIGH

live market

no missing data

recommendation deterministic

MEDIUM

2 unavailable

LOW

partial provider failure

missing market data

Label this clearly as

Recommendation Confidence

not

Bullish Confidence
