Implement the scanner trigger-contract fix identified in:

docs/SCANNER_TRIGGER_CONTRACT_AUDIT.md

IMPORTANT

The audit confirmed:

1. server/opportunity-service.ts currently hardcodes:

entryTriggerPrice: null

even though every ScanResult already exposes the breakout level as:

result.resistance

2. The webhook/automation ingestion path already persists the correct value using:

entryTrigger: scanResult.resistance

3. toInternalSetup maps resistancePrice to technicalObjective but does not use it as a trigger fallback.

4. Status normalization may return READY or TRIGGERED even when trigger is null.

5. The MCP ranker is correct and must not be weakened.

Do not modify MCP.
Do not change ranking algorithms.
Do not fabricate trigger levels.
Do not alter scanner detection algorithms.

Do not commit, push, or deploy automatically.

==================================================
1. FIX SCHEDULED OPPORTUNITY INGESTION
==================================================

In server/opportunity-service.ts, replace the hardcoded null trigger assignment with the scanner-produced resistance level.

Use the appropriate existing field names and types, equivalent to:

entryTriggerPrice: result.resistance ?? null

Requirements:

- preserve null when resistance is absent or invalid
- reject NaN, Infinity, zero, or negative values according to existing validation conventions
- do not derive a trigger from current price, major high, technical objective, or arbitrary percentages
- preserve the existing invalidation and objective mappings

==================================================
2. FIX INTERNAL API MAPPING
==================================================

Update toInternalSetup so trigger mapping uses the stored trigger first, then the resistance field as a backward-compatible fallback.

Equivalent behavior:

triggerPrice =
  row.entryTriggerPrice
  ?? row.resistancePrice
  ?? null

Return the existing trigger object shape:

trigger: triggerPrice != null
  ? {
      price: triggerPrice,
      basis: "breakout level"
    }
  : null

Do not use resistancePrice as both trigger and objective without explicitly preserving the intended existing technicalObjective behavior.

If the stored schema uses the same resistance field for both breakout entry and technical objective, document that limitation and avoid inventing a second level.

Create a safe, idempotent backfill for eligible rows:

- entryTriggerPrice is null

Do not backfill event-triggered or session-sensitive strategies blindly.

Provide either:

==================================================
4. ORB AND GAP SESSION EXPIRY
==================================================

Implement or verify session-expiry handling for:

- ORB5
- ORB15
- GAP_AND_GO

These strategies must not remain actionable as fresh daily opportunities after their valid trading session has expired.

Rules should be deterministic and timezone-aware.

Use the exchange/session timezone already used by the application.

Expired session setups should become:

- stale
- expired
- invalid

according to the existing lifecycle contract.

Do not preserve an old intraday trigger as a fresh actionable level on a later day.

==================================================
5. STATUS CONSISTENCY
==================================================

Audit normalizeStatus.

Do not allow READY or TRIGGERED to imply an actionable trade when no trigger is available.

Preferred behavior:

- keep the raw scanner stage in details
- normalize to forming/watch/unknown when an actionable price trigger is required but missing
- or preserve READY/TRIGGERED but include:
  triggerAvailable: false
  actionable: false

Choose the smallest backward-compatible option.

Do not silently downgrade event-triggered strategies if their trigger semantics are not price-based; classify them explicitly.

Document the final rule.
