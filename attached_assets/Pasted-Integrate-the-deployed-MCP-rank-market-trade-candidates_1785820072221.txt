Integrate the deployed MCP rank_market_trade_candidates tool into VCP Trader Ask AI and the AI Command Center.

CURRENT STATE

The MCP server now exposes 20 read-only tools, including:

rank_market_trade_candidates

The tool returns:

{
  request,
  reviewedCount,
  qualifiedCount,
  watchCount,
  rejectedCount,
  unavailableCount,
  candidates,
  watchCandidates,
  rejectionSummary,
  generatedAt
}

VCP Trader currently uses the older opportunity-search path for broad prompts such as:

- Find three bullish trades
- Find a stock trade under $300 risk
- Find a trade under $500 max loss
- What should I trade today?

GOAL

Use the deterministic ranked market-search engine for market-wide trade requests.

Do not duplicate MCP ranking, risk, confluence, qualification, or options-selection logic.
Do not modify scanner algorithms.
Do not change MCP transport/authentication.
Do not add execution.
Do not auto-open Trade Builder.
Do not allow OpenAI to override MCP buckets or verdicts.
Do not commit, push, or deploy automatically.

==================================================

- direction
- instrumentPreference

- requestedStrategy

"Find an options trade under $500 max loss"
→ instrumentPreference: options
→ maxRiskDollars: 500
→ numberOfIdeas: 1
→ no symbol

Do not regress the false-ticker protections. UNDER, MAX, LOSS, STOCK, RISK and similar words must never become symbols.

==================================================
4. MCP INVOCATION
==================================================

Call rank_market_trade_candidates once per request.

Use a suitable tool-specific timeout because ranking may enrich several candidates.

Do not ask OpenAI to select symbols before the MCP call.

Pass no:

- user ID
- account ID
- connection ID
- broker token
- API key
- credentials

5. STRUCTURED RESPONSE
==================================================

Add an optional response field:

rankedTradeSearch: {
  request,
  reviewedCount,
  qualifiedCount,
  watchCount,
  rejectedCount,
  unavailableCount,
  candidates,
  watchCandidates,
  rejectionSummary,
  generatedAt
}

Add:

rankedTradeSearchFailed?: boolean

Validate defensively.

Important count semantics:

- reviewedCount is the number of raw stored opportunities reviewed
- qualified/watch/rejected/unavailable count post-confluence candidates
- therefore bucket counts may not sum to reviewedCount

Label reviewedCount as:

"Stored opportunities reviewed"

Do not imply it is the same population as the post-confluence buckets.

6. PAGE HEADLINES
==================================================

Use deterministic rules:

Qualified candidates returned:
"Three bullish trade candidates identified."

Mixed:
"Eight opportunities were reviewed; two qualified and three are worth watching."

Watch only:
"No trade candidates currently qualify, but three setups are worth watching."

All rejected:
"Setups were reviewed, but none currently qualify as trades."

Unavailable:
"Trade ranking is temporarily limited by unavailable market data."

Never call rejected or watch-only setups "trade ideas."
