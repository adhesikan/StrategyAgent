PRIMARY REPOSITORY

VCP Trader AI / StrategyAgent

CURRENT PRODUCT STATE

The following work is already complete and must be preserved:

- Sprint 1: production Opportunity Engine and database-first market history
- Sprint 2.0: opportunity lifecycle
- Sprint 2.0.1: dashboard UX polish
- Sprint 2.1.1: Evidence Engine

- Sprint 2.2: deterministic Trade Structure Engine
- Opportunity research route regression fix
- Research Package route is working in production
- Broker-connected and disconnected presentation already exists
- No synthetic option contracts, premiums, Greeks, quotes or fabricated execution data are allowed

The current Research Package page is functional and visually strong, but the Overview experience still has several UX issues:

- the thesis can sound generic or internally inconsistent
- a bullish qualified candidate may display a bearish-looking badge
- evidence is difficult to compare quickly
- stock planning fields display unhelpful dashes
- warnings are presented as one long undifferentiated list
- the next action is not visually dominant
- market context is fragmented
- congressional evidence is not prominent enough
- the page does not answer the trader’s key questions quickly enough

This sprint must refine the existing experience without introducing another architecture change.

====================================================================
OBJECTIVE
====================================================================

Polish the existing Research Package into an institutional-quality decision-support interface.

The page should answer these questions within approximately 10 seconds:

1. Why did this candidate qualify?
2. What is the current research posture?
3. What supports or weakens the thesis?
4. What stock or options structure is being considered?
5. Which values are available, unresolved or broker-dependent?
6. What are the major risks?
7. What should the user review next?
8. How can a connected user proceed toward InstaTrade™?

This sprint is presentation, composition and wording only.

Do not build new market-data, scoring, planning or execution capabilities.

2. RESEARCH THESIS CARD
====================================================================

Refine the existing ResearchDecisionCard or equivalent Overview thesis component.

The thesis must be concise, specific and deterministic.

Maximum:

- one concise title line
- one short paragraph of approximately 2–4 sentences
- one small compliance line

The summary should use only existing fields such as:

- symbol
- strategy
- qualification status
- rank
- market regime
- lifecycle state
- confidence label
- whySelected
- warnings
- setup status

Preferred structure:

Research Thesis

“PLTR qualified because the deterministic scanner identified a fresh
Volume Surge setup. It currently ranks #2 among the latest qualified
candidates and is being evaluated within a Strong Bull market regime.
Four active warnings reduce the strength of the current research posture.”

Do not use a generic essay.

Do not invent catalysts, volume percentages, support levels or market facts.

If relevant fields are missing, say:

- “The available scanner output does not include a detailed qualification explanation.”
- “Market-regime context is unavailable.”
- “Confidence has not been resolved by the current deterministic output.”

3. RESEARCH POSTURE BADGE
====================================================================

Audit the current Bullish / Neutral / Bearish badge mapping.

The badge must not contradict the actual candidate data.

Use existing deterministic fields only.

Recommended display vocabulary:

- Bullish
- Constructive
- Neutral
- Defensive
- Bearish
- Unrated

Rules:

- a bullish candidate should never display Bearish due only to warning count
- warnings may reduce the posture from Bullish to Constructive or Unrated
- warnings must not reverse the direction unless an existing deterministic field explicitly says the thesis is bearish
- missing confidence or incomplete evidence should produce Unrated, not Bearish
- RISK_OFF market context may produce Defensive only if the current deterministic mapping already supports that interpretation
- do not add a new backend score

Add narrowly scoped tests covering the contradictory case visible in production:

- bullish qualified candidate
- triggered bullish setup
- multiple warnings
- no explicit bearish thesis

Expected badge:

Constructive, Bullish or Unrated according to the existing deterministic fields—never Bearish without a bearish signal.
