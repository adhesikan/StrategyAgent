====================================================================
OBJECTIVE
====================================================================

Build a provider-neutral Live Contract Resolver.

The resolver converts an illustrative options structure into one or more verified,
currently listed option-contract candidates.

The workflow must be:

Research Candidate
    ↓
Trade Structure Engine
    ↓
Illustrative Structure + DTE + Strike Framework
    ↓
Broker Capability Check
    ↓
Live Options Chain
    ↓
Expiration Resolution
    ↓
Strike Resolution
    ↓
Liquidity and Quote Validation
    ↓
Verified Contract Candidates
    ↓
Review with InstaTrade™

This sprint does not submit orders.

This sprint does not auto-trade.

This sprint does not bypass the broker abstraction.

====================================================================
PRODUCT PRINCIPLES
====================================================================

1. Research Mode without a brokerage remains fully functional.

2. Live contracts are shown only when supplied by an entitled provider.

3. No fabricated contract, expiration, strike, premium, Greek, open interest,
   volume, bid, ask or probability may be shown.

4. Missing capabilities must produce an honest unavailable state.

5. One provider failure must not break the Research Package.

6. The user always chooses whether to continue.

7. Contract resolution is planning and verification, not a recommendation.

====================================================================
EXPIRATION RESOLUTION
====================================================================

Resolve actual listed expiration dates from the connected provider.

Given:

- target minimum DTE
- target maximum DTE
- current date
- listed expirations

Rules:

1. Filter expired contracts.

2. Prefer expirations within the target DTE range.

3. If multiple expirations qualify:
   - prefer the expiration closest to the midpoint of the DTE range;
   - preserve alternatives immediately above and below where useful.

4. If no expiration exists inside the range:
   - optionally return the nearest listed expiration;
   - label it as outside the target range;
   - never pretend it matches the requested DTE.

5. Exclude contracts expiring before upcoming earnings when the existing
   planning rules require avoiding earnings, if that rule is already available.

6. Do not invent weekly or monthly expirations.

Output:

ExpirationCandidate {
  expiration: string;
  dte: number;
  withinTargetRange: boolean;
  distanceFromTargetMidpoint: number;
  warnings: string[];
}

====================================================================
STRIKE RESOLUTION
====================================================================

Map illustrative strike guidance to actual listed strikes.

Supported guidance examples:

- Near ATM
- One strike ITM
- 2–5% OTM
- Near support
- Below support
- Near breakout
- Near technical objective
- Short strike near objective

Rules:

Near ATM:
- choose the listed strike with the smallest absolute distance from underlying price.

One strike ITM:
- identify ATM;
- select the immediately adjacent in-the-money strike when available.

2–5% OTM:
- filter listed strikes within the requested percentage band;
- rank by closeness to the midpoint.

Near support:
- choose the listed strike closest to support;
- preserve whether it is above or below support.

Near technical objective:
- choose the listed strike closest to the current objective.

For spreads:

Bull Call Spread:
- long call near ATM or configured long-leg framework;
- short call near the technical objective or configured short-leg framework;
- long strike must be below short strike.

Bull Put Spread:
- short put near or below support;
- long put below the short put;
- width must be a listed and valid spread width.

Never create a synthetic strike that is absent from the chain.

====================================================================
PRICING AND SPREAD CALCULATIONS
====================================================================

Use only actual provider quotes.

For a single contract:

- display bid;
- ask;
- mark only if supplied or deterministically computed as midpoint and clearly labeled;
- last;
- quote timestamp.

If computing midpoint:

mark = (bid + ask) / 2

Only when both bid and ask are valid.

Label:

“Calculated midpoint”

For vertical spreads:

Estimated debit or credit may be calculated from current leg quotes.

Bull Call Spread debit framework:

estimatedDebit =
  longCallAsk - shortCallBid

Bull Put Spread credit framework:

estimatedCredit =
  shortPutBid - longPutAsk

Clearly label these as:

- Estimated from current displayed quotes
- Not a guaranteed fill
- Verify in broker order preview

Never use stale or missing quote values to calculate a spread price.

If required leg prices are unavailable:

- display “Pricing unavailable”;
- preserve the contract candidates;
- do not invent a price.

====================================================================
MAXIMUM RISK AND MAXIMUM GAIN
====================================================================

Only calculate when inputs are complete and mathematically defined.

Long Call:
- max risk = displayed premium × multiplier;
- max gain = theoretically unlimited;
- breakeven = strike + premium.

Cash-Secured Put:
- max risk = (strike - premium) × multiplier;
- max gain = premium × multiplier;
- breakeven = strike - premium.

Covered Call:
- show assignment and upside-cap characteristics;
- do not claim full max-risk values without verified stock cost basis.

Bull Call Spread:
- spread width = short strike - long strike;
- max risk = net debit × multiplier;
- max gain = (spread width - net debit) × multiplier;
- breakeven = long strike + net debit.

Bull Put Spread:
- spread width = short strike - long strike;
- max gain = net credit × multiplier;
- max risk = (spread width - net credit) × multiplier;
- breakeven = short strike - net credit.

Requirements:

- calculate only from verified contract strikes and actual displayed quotes;
- identify the quote basis used;
- label calculations as estimates;
- never present estimated values as guaranteed outcomes;
- hide calculations when required data is missing.
