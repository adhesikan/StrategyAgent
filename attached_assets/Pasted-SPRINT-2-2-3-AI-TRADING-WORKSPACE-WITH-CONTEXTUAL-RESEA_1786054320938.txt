SPRINT 2.2.3 — AI TRADING WORKSPACE WITH CONTEXTUAL RESEARCH ASSISTANT

PRIMARY REPOSITORY

VCP Trader AI / StrategyAgent

====================================================================
CURRENT PRODUCT STATE
====================================================================

The following capabilities are complete and must be preserved:

- PostgreSQL-first historical market data
- Twelve Data ingestion
- broker abstraction for current and future supported brokerages
- Opportunity Engine
- opportunity lifecycle and persisted snapshots
- Research Package
- Evidence Engine
- Professional Research Cards
- Research Decision Engine
- Trade Structure Engine
- Research Experience Refinement
- Live Options Contract Resolver
- congressional disclosure integration
- news and sentiment evidence
- market-regime context
- deterministic risk and trade-planning logic
- conditional Review with InstaTrade™ workflow
- existing Ask AI capability
- no synthetic market prices or fabricated options contracts in production

The application currently has strong components, but the research experience is
distributed across tabs and cards.

This sprint must unify those existing capabilities into one flagship workflow.

====================================================================
VISION
====================================================================

Create the AI Trading Workspace: the primary destination a trader enters after
selecting a research candidate.

The workspace should guide the user through one coherent journey:

Discover
    ↓
Understand
    ↓
Evaluate Evidence
    ↓
Review Decision Logic
    ↓
Plan Stock or Options Structure
    ↓
Resolve Live Contracts, when supported
    ↓
Assess Risk
    ↓
Ask Contextual Questions
    ↓
Prepare for InstaTrade™ Review

The user should not feel as though they are navigating several disconnected tools.

This is primarily a composition, navigation and user-experience sprint.

It is not a new scanner, ranking engine, data provider or execution system.

====================================================================
PRIMARY OBJECTIVE
====================================================================

Transform the existing /research/:symbol experience into a unified,
institutional-quality AI Trading Workspace.

The workspace must answer these questions quickly:

1. Why did this candidate qualify?
2. What is the current research thesis?
3. What evidence supports or weakens it?
4. What would invalidate it?
5. Which stock structure fits the setup?
6. Which illustrative options structure fits the setup?
7. Are verified live contracts available through the connected broker?
8. What are the major risks?
9. What changed since the previous scan?
10. What should the user review next?
11. What questions can the user ask about this exact candidate?
12. How can the user continue toward InstaTrade™ review?

====================================================================

====================================================================

Before implementing the assistant panel, audit:

- current Ask AI component

- whether it supports preloaded research context
- whether it already calls MCP deterministically
- current response citations/source labels
- current conversation-state behavior
- current caching
- current token and payload limits

Preferred request pattern:

{
  question: "...",
  symbol: "PLTR",
  contextMode: "trading_workspace",
  optionalSelectedContractId: "..."
}

The backend should resolve authoritative context itself when practical.

Do not trust client-submitted prices, evidence or risk values as authoritative.

If the existing endpoint cannot accept additive context safely, make the smallest
backward-compatible extension necessary.

Do not create a new AI provider.

====================================================================
ASSISTANT RESPONSE RULES
====================================================================

The contextual assistant must:

- use deterministic workspace facts as the primary source
- clearly distinguish factual values from explanation
- say when data is unavailable
- avoid inventing prices, contracts, news or evidence
- avoid personalized investment advice
- avoid instructing the user to buy or sell
- avoid claiming probability of success
- avoid claiming Congress activity predicts returns
- avoid treating an illustrative structure as a verified live contract
- identify quote source and timestamp when discussing live contracts
- preserve existing disclaimers
- keep responses concise by default
- link or guide the user to the relevant workspace section

Preferred language:

- “The deterministic scanner qualified this candidate because…”
- “The current evidence supports…”
- “The following factors weaken the research thesis…”
- “The options structure is illustrative until verified through a connected broker.”
- “The selected contract candidate was resolved from the connected broker’s chain as
   of…”

Avoid:

- “You should buy…”
- “The best trade for you is…”
- “This will likely make…”
- “Congress is buying, so…”
- “This contract is guaranteed…”

====================================================================
ASSISTANT FAILURE BEHAVIOR
====================================================================

The workspace must remain fully usable when:

- OpenAI API is unavailable
- API credits are exhausted
- assistant request times out
- research context is incomplete
- one evidence provider fails
- MCP is unavailable
- broker is disconnected
- live contract data is unavailable

Only the assistant panel should display the failure.

Use the existing deterministic/rule-based fallback where available.

Do not let assistant failure break the workspace.

====================================================================
ASSISTANT PERFORMANCE AND SAFETY
====================================================================

- do not call the AI endpoint automatically on page load
- only call when the user submits a question
- reuse existing conversation/loading patterns
- limit context payload size
- do not include broker tokens
- do not include account numbers
- do not include raw option-chain payloads
- do not include raw congressional source payloads
- do not include hidden research-save handles
- do not include execution-ready credentials
- sanitize logs
- preserve user isolation
- rate-limit through existing infrastructure
- show source/freshness labels when available
