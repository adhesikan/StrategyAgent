SPRINT 2.2.3 — WORKSPACE SCROLL AND SECTION-NAVIGATION REGRESSION FIX

Repository:
VCP Trader AI / StrategyAgent

CURRENT PRODUCTION DEFECT

The AI Trading Workspace renders, but:

1. The user cannot scroll down through the full Workspace.
2. Clicking section-navigation items such as:
   - Summary
   - What Changed
   - Decision
   - Evidence
   - Trade Planning
   - Live Contracts
   - Risk
   - Congress / News
   - Ask VCP AI
   - InstaTrade™
   - Scan History

does not move to the corresponding section.

This is a blocking UX regression found during production UAT.

Do not add features.
Do not redesign the Workspace.
Do not modify backend APIs, Opportunity Engine, MCP, broker integrations,
Live Contract Resolver, assistant behavior, database, routes or business logic.

Fix scrolling and section navigation only.

====================================================================
1. REPRODUCE AND IDENTIFY THE ACTUAL SCROLL CONTAINER
====================================================================

Inspect the full layout hierarchy for /research/:symbol:

- application shell
- page layout
- main content wrapper
- opportunity-research page
- Workspace tab wrapper
- workspace navigation
- workspace section container
- assistant drawer wrappers

Search for styles or classes including:

- overflow-hidden
- overflow-y-hidden

- overflow-y-auto
- h-screen
- min-h-screen
- max-h-screen
- h-full
- fixed
- absolute

Determine:

- whether a nested <main> element is intended to scroll;
- whether opening or mounting the assistant drawer applies a permanent body-scroll lock;
- whether a fixed-height parent clips the Workspace content;
- whether a transparent overlay intercepts wheel or touch events.

Document the exact root cause before changing code.

====================================================================
2. RESTORE NORMAL VERTICAL SCROLLING
====================================================================

Preferred behavior:

- the main page/document scrolls normally;
- the Workspace may grow naturally with content;
- no fixed height clips sections;
- sticky navigation remains sticky without becoming the scroll container;
- the assistant drawer locks body scrolling only while visibly open;
- closing or unmounting the drawer always restores scrolling.

Avoid creating a second nested vertical scrollbar unless the existing application
shell intentionally uses one.

If the application shell already has a canonical scroll container, use that same
container consistently.

Requirements:

- mouse wheel works;
- trackpad works;
- Page Up / Page Down works;
- Space and Shift+Space work where appropriate;
- touch scrolling works on mobile;
- scrollbar is visible according to existing design;
- scrolling reaches Scan History and the final page footer;
- no content is clipped.

Audit:

Add development-time/test validation proving:

- no duplicate IDs occur;
- no nav item points to a missing section.

====================================================================
4. FIX CLICK-TO-SCROLL BEHAVIOR
====================================================================

Clicking a workspace navigation item must scroll to the correct section.

Use the correct scroll container.

If the document scrolls:

target.scrollIntoView({
  behavior: reducedMotion ? "auto" : "smooth",
  block: "start"
});

If a nested canonical container scrolls:

- calculate the target offset relative to that container;
- call scrollContainer.scrollTo(...);
- do not use window scrolling.

Account for sticky headers.

Preferred CSS:

scroll-margin-top

on each section rather than hardcoded JavaScript offsets where practical.

Example:

.workspace-section {
  scroll-margin-top: var(--workspace-sticky-offset);
}

The final position must not hide the section heading behind:

- global top navigation;
- data-source banner;
- tab bar;
- workspace section navigator.

====================================================================
5. FIX ACTIVE-SECTION TRACKING
====================================================================

Audit useActiveSection and IntersectionObserver.

Common failure cases to check:

- observer root is null but a nested container actually scrolls;
- observer root references the wrong element;
- thresholds are too strict;
- rootMargin hides all intersections;
- refs are attached before sections render and never re-observed;
- IDs do not match;
- sticky header covers the observed region;
- observer is recreated repeatedly;
- sections rendered conditionally are not registered.

Requirements:

- active pill updates while scrolling;
- clicking a pill activates it immediately;
- observer later confirms the correct active section;
- optional/missing sections do not break tracking;
- first section is active near the top;
- last section can become active near the bottom.

Use the actual scroll container as IntersectionObserver.root when scrolling is nested.

Provide a robust fallback for browsers/tests without IntersectionObserver.

====================================================================
6. ASSISTANT DRAWER SCROLL-LOCK AUDIT
====================================================================

The contextual assistant introduced both:

- a desktop assistant panel/drawer;
- a mobile bottom sheet.

Verify that scroll-lock logic:

- activates only while the modal drawer is open;
- does not activate merely because the drawer component is mounted;
- restores the previous body overflow value on close;
- restores overflow on component unmount;
- handles route changes;
- handles Escape;
- does not leave body.style.overflow = "hidden";
- does not mount a full-screen overlay with pointer events while closed.

If using an existing Dialog/Sheet component, confirm its open prop is correctly
controlled.

Do not remove accessibility focus trapping while the drawer is genuinely open.

====================================================================
7. STICKY NAVIGATION LAYOUT
====================================================================

Keep the workspace section navigation sticky, but make sure it does not block scroll.

Requirements:

- sticky, not fixed, unless the existing layout requires fixed;
- correct top offset beneath the application header and tab bar;
- horizontal overflow is allowed on mobile;
- no invisible full-width overlay extends below the nav;
- pointer events apply only to visible nav controls;
- z-index does not prevent interaction with content;
- nav does not create a fixed-height parent.

Use:

position: sticky

and avoid wrapping the entire Workspace in a viewport-height container.

====================================================================

If hash navigation is already implemented, preserve it.

If not already implemented, do not add complex routing.

Only implement this if it is simple and does not interfere with Wouter/current routing.

====================================================================
9. ACCESSIBILITY
====================================================================

Section navigation should use appropriate semantics:

- nav aria-label="Workspace sections"
- buttons or anchors with clear accessible names;
- aria-current="location" or equivalent on active item;
- visible focus state;
- Enter and Space activate button items;
- reduced-motion preference disables smooth scrolling;
- focus should not unexpectedly jump on mouse click;
- keyboard users can reach each section;
- headings have tabindex="-1" only if programmatic focus is intentionally used.

Do not automatically move keyboard focus on every scroll event.
