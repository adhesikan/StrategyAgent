SPRINT 2.2.5 — INSTITUTIONAL INTELLIGENCE BACKGROUND OPERATIONS

Repository:
VCP Trader AI / StrategyAgent

OBJECTIVE

Institutional Intelligence must no longer block the primary VCP Trader AI roadmap.

The SEC parser is proven operational:

- official SEC catalog discovery works
- current post-2023 datasets download correctly
- SUBMISSION.tsv parses correctly
- COVERPAGE.tsv parses correctly
- INFOTABLE.tsv parses correctly
- current SEC headers and date formats are supported
- millions of holdings join successfully
- common-stock filtering works

Current production limitation:

2025-Q4:
eligibleCommonStockRows: 3,331,742
persistence throughput: approximately 195 holdings/sec
application timeout: approximately 20 minutes
approximately 824 / 9,364 accessions processed before timeout

The immediate goal is NOT to fully optimize the entire ingestion pipeline.

Instead, operationalize Institutional Intelligence as a safe, scheduled, resumable
background workflow so development can continue on the main VCP Trader roadmap.

Do not redesign the SEC parser.

Do not block the product roadmap on historical backfill completion.

Keep:

INSTITUTIONAL_INTELLIGENCE_ENABLED=false

until minimum data readiness is reached.

====================================================================
1. DAILY SEC CATALOG CHECK
====================================================================

Create a scheduled institutional refresh entry point.

Example:

scripts/run-institutional-daily.ts

Behavior:

1. fetch official SEC 13F catalog
2. identify latest published dataset(s)
3. compare against ingestion DB
4. if no new/incomplete dataset exists:
   log "institutional_refresh_no_work"
   exit successfully
5. if work exists:
   process/resume it

The daily job must NOT redownload/reprocess completed quarters unnecessarily.

13F datasets are quarterly, so daily checking is sufficient.

====================================================================
2. RESUMABLE CHUNK MODE
====================================================================

Introduce bounded persistence work per scheduled invocation.

Example configuration:

INSTITUTIONAL_ACCESSIONS_PER_RUN=500

or choose an appropriate safe value based on production timing.

Each scheduled run:

- resumes incomplete quarter
- identifies completed accessions
- processes the next bounded group
- persists holdings
- checkpoints
- exits successfully

Do NOT intentionally run into the 20-minute timeout.

Target scheduled execution time:

< 10–15 minutes per invocation

with safety margin.

====================================================================
3. PRIORITY ORDER
====================================================================

Scheduled work priority:

1. stale/incomplete latest quarter
2. latest unprocessed quarter
3. previous quarter required for comparison
4. optional historical backfill

Do not spend scheduled resources backfilling old history before the two most useful
comparable quarters are ready.

For current production prioritize:

2026-Q1
2025-Q4

====================================================================
4. QUARTER STATE MACHINE
====================================================================

Use clear quarter states:

NOT_STARTED
PARSING
PERSISTING
PARTIAL
READY_FOR_MAPPING
AGGREGATING
READY
FAILED

Legacy run statuses may remain for audit, but derive operational state consistently.

A quarter is READY only when persistence reconciliation succeeds.

====================================================================
5. ACCESSION CHECKPOINTING
====================================================================

Track progress at accession granularity.

For each quarter expose:

totalAccessions
processedAccessions
remainingAccessions
storedFilings
storedHoldings
lastHeartbeat
lastScheduledRun
progressPercent

A scheduled rerun must continue from existing completed accessions.

Never duplicate holdings.

Never treat presence of a filing row alone as proof that an accession is complete
unless all expected holdings have been persisted.

====================================================================
6. REMOVE INTERACTIVE-SHELL DEPENDENCY
====================================================================

The scheduled workflow must run independently from Railway shell sessions.

Closing a browser or shell must have no impact.

The job must be invokable as:

npx tsx scripts/run-institutional-daily.ts

and be suitable for Railway Cron / scheduled execution.

Do not require an operator to keep a shell open.

====================================================================
7. STALE RUN CLEANUP
====================================================================

At the beginning of each scheduled invocation:

detect stale "running" attempts.

If heartbeat exceeds threshold:

mark old attempt interrupted/partial

and resume safely.

No stale run should remain "running" indefinitely.

====================================================================
8. AUTOMATIC AGGREGATION AFTER COMPLETION
====================================================================

Do NOT rebuild aggregates after every 500-accession chunk.

Only when a quarter becomes persistence-complete:

1. run mapping
2. rebuild institutional aggregates
3. run data-quality validation
4. update quarter state

This keeps scheduled jobs efficient.

====================================================================
9. AUTOMATIC READINESS GATE
====================================================================

After aggregate rebuild, automatically evaluate:

- latest quarter available
- previous comparable quarter available
- mapping coverage
- aggregate rows exist
- data quality checks pass

Do NOT automatically enable:

INSTITUTIONAL_INTELLIGENCE_ENABLED

The flag remains an explicit deployment/operator decision.

But expose:

institutionalDataReady: true/false

so activation becomes simple later.

====================================================================
10. CURRENT PARTIAL DATA
====================================================================

Safely recover current production state.

2026-Q1 has a legacy incomplete run incorrectly marked completed.

2025-Q4 has partial persistence from interrupted attempts.

Normal scheduled processing must:

- recognize both as incomplete
- retain valid persisted work
- finish remaining work
- reconcile counts
- eventually mark them READY

Do not require --force.

====================================================================
14. FAILURE BEHAVIOR
====================================================================

One failed daily run must not break the product.

If Institutional processing fails:

- existing institutional data remains available
- latest READY quarter remains active
- failure is logged
- next scheduled execution retries/resumes
- other VCP Trader features remain unaffected

Institutional Intelligence is an enhancement, not a dependency for:

Opportunity Engine
Decision Engine
Trade Structure Engine
Live Contracts
InstaTrade
VCP AI
