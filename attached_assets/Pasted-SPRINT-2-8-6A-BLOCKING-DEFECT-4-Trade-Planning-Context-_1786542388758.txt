SPRINT 2.8.6A — BLOCKING DEFECT-4
Trade Planning Context Returns 401 for Authenticated User

PRODUCTION EVIDENCE

The remaining TEST_LIVE certification blocker has now been isolated.

Browser Network inspection on Railway production shows:

GET /api/trade-planning/WMT/context
HTTP 401 Unauthorized

Request URL:
https://www.vcptrader.com/api/trade-planning/WMT/context

The browser request contains the normal application session cookie.

At essentially the same time, the same browser/session successfully calls other authenticated endpoints including:

GET /api/auth/user → 200
GET /api/user/settings → 200/304
GET /api/opportunities/today → 200/304
GET /api/opportunities/workspace/WMT → 200

Production Opportunity Workspace also returns:

symbol: WMT
opportunity: non-null
tradePlanningEligible: true

Therefore:

THIS IS NOT CURRENTLY AN OPPORTUNITY QUALIFICATION DEFECT.

Do not make additional changes to Opportunity Engine qualification, ranking thresholds,
snapshot hydration, TEST_LIVE symbol allowlists, or execution gates unless investigation
proves they are independently defective.

The immediate defect is:

/api/trade-planning/WMT/context returns 401 for an otherwise authenticated session.

There is also a client error-handling defect:

the Trade Planning page converts this 401 into:

"WMT is not a current research candidate"

which is factually incorrect.
