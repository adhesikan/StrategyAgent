SPRINT 2.8.7 — BI-004 / TASK #161
BROKER-INDEPENDENT PLANNING CAPITAL & RISK SIZING

We have completed the V1 brokerless options scope decision.

The next approved broker-independence backlog item is:

BI-004 / Task #161:
Allow users to enter hypothetical/user-defined available planning capital
so risk sizing and Trade Plan Readiness can operate without a broker.

This resolves CON-004.

IMPORTANT:
This is PLANNING capital, NOT broker buying power.
It must never authorize execution.

============================================================
OBJECTIVE
============================================================

A user without a broker connection should be able to provide planning
assumptions such as:

Planning Capital: $25,000
Maximum Risk Per Trade: 2%
Maximum Position Allocation: 10%

VCP Trader AI can then calculate:

Maximum Risk Dollars = $500

Maximum Position Allocation = $2,500

and use these values for RESEARCH / PLANNING risk analysis.

These are hypothetical planning constraints.

They are NOT actual broker buying power.

============================================================
DATA MODEL
============================================================

First determine whether the existing planningSnapshot/riskSnapshot can
store these values without a schema migration.

Prefer existing JSONB structures if semantically appropriate.

Suggested conceptual model:

PlanningCapitalContext {
  capitalAmount
  maxRiskPercent

Do not use this exact type if an existing canonical model already covers it.

============================================================
NO-BROKER BEHAVIOR
============================================================

When no broker is connected:

Trade Plan Readiness should be able to use user-defined planning capital.

Example:

Planning Capital       $25,000
Max Risk / Trade       2%
Maximum Risk           $500
Max Allocation         10%
Maximum Position       $2,500

Dim 7 must NOT pretend this is broker buying power.

Use planning semantics such as:

PLANNING_MODE

and clearly identify:

"Using user-defined planning capital"

BrokerExecutionReadiness remains:

NOT_CONNECTED

executionAvailable remains:

false

overallStatus must NEVER become PASS merely because planning capital exists.

============================================================
BROKER-CONNECTED BEHAVIOR
============================================================

When a broker is connected:

Preserve user-defined planning capital as a planning assumption.

Broker actual buying power remains independently evaluated for execution.

DO NOT overwrite planning capital with broker buying power.

Conceptually:

PLAN:
User-defined planning capital = $25,000

EXECUTION:
Broker buying power = $43,750

Both may coexist.

The planning engine uses the planning assumption.

Execution readiness uses actual broker account data.

============================================================
RISK SIZING
============================================================

Reuse the existing risk/position-sizing engine wherever possible.

For equity planning, calculate appropriate position sizing using:

- planning capital
- max allocation
- max risk
- planned entry
- stop/risk distance where available

For theoretical options:

Theoretical premiums may be used ONLY for hypothetical scenario/risk
research consistent with Invariant C1.

They must not become executable prices.

If sufficient inputs do not exist:

return NOT_CONFIRMED / UNAVAILABLE as appropriate.

Never fabricate missing values.
