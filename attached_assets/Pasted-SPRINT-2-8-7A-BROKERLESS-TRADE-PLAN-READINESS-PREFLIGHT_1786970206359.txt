SPRINT 2.8.7A — BROKERLESS TRADE PLAN READINESS & PREFLIGHT SPLIT

STATUS

Audits A, B, C, C1, and D are complete.

This sprint implements ONLY the first P0 architecture package:

- BI-001 / BI-002 — Execution Preflight two-layer split
- BI-014 — Trade Plan execution section brokerless behavior
- related P0 broker-connected render gates required to expose Trade Plan Readiness

DO NOT implement:
- independent options provider
- theoretical options engine
- dashboard portfolio redesign
- options scanner redesign
- onboarding/guided journey
- broad market-data abstraction beyond what is required here

============================================================
PRIMARY GOAL
============================================================

A user WITHOUT a broker connection must be able to:

- open a saved Trade Plan
- run Trade Plan Readiness
- see independent readiness dimensions
- receive a meaningful PASS / REQUIRES_REVIEW / FAIL result
- continue monitoring/researching the plan

Broker absence must NOT be shown as a plan failure.

However:

Trade Plan Readiness PASS must NEVER authorize order preparation or broker submission.

============================================================

============================================================

Add canonical types in shared execution types for:

TRADE_PLAN_READINESS

BROKER_EXECUTION_READINESS

  status: "PASS" | "FAIL" | "REQUIRES_REVIEW",
  label,

  brokerConnected,

executionAvailable: boolean

Preserve existing overallStatus.
