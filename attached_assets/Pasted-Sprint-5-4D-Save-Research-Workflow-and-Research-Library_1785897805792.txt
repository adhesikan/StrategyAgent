Sprint 5.4D — Save Research Workflow and Research Library

CURRENT STATE

The backend now provides:

researchSave?: {
  available: true;
  handleId;
  domain;
  titleSuggestion;
  tagSuggestions;
  expiresAt;
}

The backend also exposes authenticated research-record endpoints under:

/api/research-records

Research evidence is deterministic, immutable and stored only after explicit user action.

GOAL

Allow users to:

- explicitly save a deterministic research result
- see whether it was saved
- browse their saved research records
- filter and search saved research
- edit only user-owned metadata
- archive or delete saved research
- open a saved record summary

This is a research and decision-support workflow.

Do not:

- modify MCP
- modify TraderBrain decisions
- modify scanner, ranking, recommendation, risk, portfolio or options logic
- accept arbitrary evidence from the browser
- expose evidence save handles outside the authenticated session flow
- add automatic saving
- add execution
- commit, push or deploy automatically

Use the actual implementation.

==================================================
2. SAVE RESEARCH ACTION
==================================================

When an Ask AI response contains researchSave.available === true, render:

Save Research

The button must submit only the backend-issued save handle and approved user metadata.

Do not submit:

- ResearchEvidenceRecord
- tool payloads
- MCP results
- account IDs
- context tokens
- raw portfolio data

Suggested interaction:

1. User clicks Save Research.
2. Open a small dialog.
3. Prefill:
   - titleSuggestion
   - tagSuggestions
4. Allow editing:
   - title
   - tags
   - optional user label
5. Submit the opaque handle.
6. Show a clear saved state.

==================================================
3. HANDLE EXPIRY AND IDEMPOTENCY
==================================================

Support:

- valid save
- handle expired
- already consumed / idempotent retry
- session mismatch
- unauthorized
- server error

For an expired handle, show:

"This research snapshot has expired. Run the analysis again to create a fresh snapshot."

Do not silently recreate evidence from client data.

Do not automatically rerun the analysis without user action.

==================================================
4. SAVE BUTTON STATES
==================================================

Support:

- Save Research
- Saving…
- Saved
- Expired
- Unavailable

Disable duplicate submissions while saving.

After successful save, store the returned research-record ID in component state so the user can open it.

Do not store the save handle in localStorage.
