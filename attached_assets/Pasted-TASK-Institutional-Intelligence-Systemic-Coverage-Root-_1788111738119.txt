PART 3 — DETERMINE ROOT CAUSES
==================================================

For each major population loss, determine the real root cause.

Investigate systemic causes including:

A. SECURITY MASTER COVERAGE

Does the canonical security master contain enough securities/CUSIPs?

If not:
- why not?
- what source populates it?
- is population incomplete?
- does ingestion only create identities opportunistically?

B. CUSIP → SYMBOL MAPPING

Determine whether mapping currently depends on:
- manually reviewed rows
- ingestion-time ticker evidence
- exact mappings
- external/reference data
- issuer-name inference
- stale ticker evidence

Determine why mapped coverage historically remained near zero despite hundreds of thousands of persisted holdings.

C. TRUST PROMOTION

Determine whether reliable evidence exists in the database but mappings are simply never promoted to reviewed/exact status.

This is critical.

Quantify:

evidence exists + deterministic identity
versus
truly ambiguous identity.

D. ISSUER NAME NORMALIZATION

Determine whether variations such as:

JPMORGAN CHASE & CO
JPMORGAN CHASE CO
JPMORGAN CHASE
etc.

prevent deterministic identity resolution.

Do NOT solve with fuzzy guessing.

If normalization is appropriate, implement deterministic canonical normalization.

E. CLASS TITLE NORMALIZATION

Determine whether common class-title variations prevent otherwise reliable mappings.

F. MULTIPLE CUSIPS

Determine how securities with:
- historical CUSIPs
- multiple share classes
- changed identifiers
- multiple legitimate filing CUSIPs

are represented.

A ticker/security may legitimately correspond to multiple CUSIPs.

Do not collapse them incorrectly.

G. HISTORICAL VS CURRENT IDENTITY

Determine whether historical holdings fail because the current security master only recognizes current CUSIPs.

H. INGESTION PIPELINE

Determine whether the normal ingestion process should have generated/promoted mappings but does not.

If so, fix the ingestion/mapping pipeline rather than requiring future repair scripts.

I. DOWNSTREAM MATERIALIZATION

Determine whether:
- mapping exists
but
- holdings are not mapped
or
- aggregates are not generated
or
- signals are not generated
or
- sector/theme snapshots are not rebuilt.

Quantify each stage independently.

PART 4 — BUILD A GENERAL RESOLUTION ENGINE
==================================================

Based on proven causes, implement a GENERAL security-resolution pipeline.

Do not create symbol-specific fixes.

The resolver should operate using deterministic evidence and produce:

RESOLVED_TRUSTED

AMBIGUOUS

CONFLICTING

UNSUPPORTED

INSUFFICIENT_EVIDENCE

as appropriate.

A mapping may be automatically promoted ONLY when identity is deterministic under explicit rules.

Examples of acceptable deterministic evidence may include:

- reviewed security master CUSIP identity
- exact canonical CUSIP relationship
- authoritative existing security reference
- exact ticker/CUSIP evidence from an approved source
- deterministic historical identity relationship

Do NOT promote merely because:
- issuer names look similar
- one probable ticker appears
- fuzzy matching gives a high score
- the ticker is popular
- the symbol exists somewhere in a filing

Create reusable resolver logic used by BOTH:

1. ongoing ingestion
2. remediation/backfill

There must not be one mapping algorithm for repair and another for future ingestion.
