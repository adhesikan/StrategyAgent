Task #197 — Populate canonical security asset types from authoritative reference evidence

DO NOT perform any production write, remediation APPLY, ingestion run,
migration execution, feature-flag activation, or manual ticker repair.

CONTEXT

Task #196 added the correct fail-closed security-type eligibility gate.

Production-wide read-only analysis now shows that the gate is excluding
essentially the entire trusted-reference universe because persisted
security_master.asset_type is missing/null.

The analyzer currently produces:

- zero eligible stock aggregate targets
- zero eligible stock signal targets
- no remediation operations

and many records show:

canonicalSecurityType = insufficient_evidence
securityTypePopulation = INSUFFICIENT_SECURITY_TYPE_EVIDENCE

with security_master.assetType = null.

This is NOT a reason to weaken Task #196.

The missing layer is:

trusted external security identity
→ authoritative instrument/security classification
→ canonical security_master.asset_type
→ Task #196 eligibility classifier

OBJECTIVE

Implement the smallest generic systemic fix that populates canonical
security_master.asset_type from authoritative security-reference
evidence already retrieved or retrievable through the approved
reference pipeline.

Do not infer asset type from ticker format or issuer name.

Do not manually classify securities.

Do not use allowlists/blocklists.

Do not weaken the Task #196 classifier.

asset_type must remain insufficient/null as appropriate.
