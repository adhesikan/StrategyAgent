Task #213 — Institutional Runtime Convergence and Population Acceptance

STOP THE ITERATIVE SYMBOL-BY-SYMBOL DEBUGGING CYCLE.

We have repeatedly fixed separate divergences between:

- canonical production analyzer/verifier
- Stock View identity
- holder enrichment
- trend
- aggregates
- signals
- security-master ticker lookup
- trusted mapping lookup

Each fix exposes another stale implementation of the same institutional
identity/data-selection contract.

OBJECTIVE

Make the Institutional Intelligence runtime converge on ONE shared canonical
security context and ONE shared set of downstream data loaders, then prove
the complete runtime population works with one production-safe acceptance
harness.

This is an architectural convergence task, not another JPM-specific fix.

DO NOT:

- run remediation
- run OpenFIGI
- run ingestion
- modify production institutional data
- add ticker allowlists
- add symbol-specific exceptions
- create another independent verifier implementation
- chase symbols one at a time

PART 7 — ACCEPTANCE CRITERIA

The sprint is complete only when a final production read-only acceptance run
shows:

- all runtime-valid canonical symbols resolve identity
- zero unexpected UNSUPPORTED results for canonical stock-eligible symbols
- zero SQL/runtime exceptions
- zero aggregate-backed symbols failing aggregate lookup
- zero signal-backed symbols failing signal lookup
- trend failures only where legitimately INSUFFICIENT_HISTORY / unavailable
- no fabricated zero holder counts
- no active UI route uses a legacy ticker-only identity path
- malformed/nonstandard symbols may remain explicitly rejected by the
  existing symbol validator
- funds/unsupported securities remain excluded

If a legitimate data-quality limitation prevents 100%, report it separately
from software/runtime failure.
