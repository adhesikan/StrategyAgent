Update the existing VCP Trader AI / Strategy Agent app to add user-directed trailing stop and position protection features using the existing broker integration architecture.

Important:
Tradier does not appear to support native trailing stop orders through the standard order API. Do NOT implement this as a native Tradier trailing_stop order type unless the broker adapter explicitly confirms support.
Instead, implement an application-managed trailing stop engine that monitors user-enabled positions and submits regular market/stop/stop-limit exit orders through the broker when the user-defined trailing condition is triggered.

Core principle:
This is NOT full automation and NOT AI trading for the user.
This is user-directed position protection.
The user must explicitly enable the exit rule, define the trailing stop parameters, and acknowledge the risks before the engine monitors the position.

Do not market this as:
- autonomous trading
- autopilot
- AI trades for you
- guaranteed protection
- guaranteed stop
- guaranteed fill

Use language:
- Position Protection
- Exit Protection
- User-defined exit rules
- Trailing stop monitoring
- Self-directed risk controls
- Application-managed exit rule

- triggerExit(plan, marketData)
- logEvent(planId, eventType, message, payload)

Create service:

TrailingStopCalculator

Logic for long positions:
- highestPriceSeen = max(highestPriceSeen, currentPrice)
- dollar trail stop = highestPriceSeen - trailValue
- percent trail stop = highestPriceSeen * (1 - trailValue / 100)
- trigger when currentPrice <= currentStopPrice

Logic for short positions:
- lowestPriceSeen = min(lowestPriceSeen, currentPrice)
- dollar trail stop = lowestPriceSeen + trailValue
- percent trail stop = lowestPriceSeen * (1 + trailValue / 100)
- trigger when currentPrice >= currentStopPrice

Support stocks first.
Support options with caution:
- For long calls/puts, trail option premium by default
- Optional setting to trail based on underlying stock price
- For spreads, initially alerts-only unless existing spread exit builder is reliable

====================================================
7. MONITORING WORKER
====================================================

Create background worker:

positionProtectionWorker

Runs during regular market hours.
Poll active plans.

Default polling:
- every 15 seconds for live mode
- every 60 seconds for paper mode

Make polling interval configurable via env:

POSITION_PROTECTION_LIVE_POLL_SECONDS=15
POSITION_PROTECTION_PAPER_POLL_SECONDS=60

Worker flow:
1. Load active plans
2. Fetch latest quote via broker adapter or paper data source
3. Update highest/lowest price seen
4. Recalculate trailing stop
5. Save updated currentStopPrice
6. If trigger condition met:
   - mark triggered
   - submit exit order if live mode
   - simulate exit if paper mode
   - log event
   - notify user if notification service exists

Important:
Use database locks or idempotency to prevent duplicate exit orders.
Before submitting exit:
- re-check plan status
- verify no submittedExitOrderId exists
- verify position quantity still exists
- verify market is open
