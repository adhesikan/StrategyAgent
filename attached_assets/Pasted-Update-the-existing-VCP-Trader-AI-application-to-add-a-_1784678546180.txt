4. INBOUND RESEND WEBHOOK
==================================================

Create a public server endpoint using the project’s current framework conventions.

Suggested endpoint:

POST /api/webhooks/resend

Requirements:

- Accept raw request content as needed for signature verification.
- Verify every webhook using RESEND_WEBHOOK_SECRET and the official Resend SDK verification method.
- Do not process unverified events.
- Return an appropriate 2xx response quickly after safely accepting a valid event.
- Make processing idempotent.
- Store the Resend webhook event ID or another unique provider identifier so duplicate deliveries are ignored.
- Log invalid signatures without logging secrets or complete sensitive payloads.
- Support at minimum:
  - email.received
  - email.sent
  - email.delivered
  - email.delivery_delayed
  - email.bounced
  - email.complained
  - email.failed
  - email.opened, only if enabled and appropriate
  - email.clicked, only if enabled and appropriate

IMPORTANT FOR email.received:
The webhook event may contain only email metadata. After verifying the event, use the Resend Receiving API and the received email ID to retrieve the complete email, including:

- from
- to
- cc
- bcc
- subject
- text body
- HTML body
- headers
- attachment metadata

Retrieve attachment information only when needed. Do not assume that the webhook payload itself contains the complete message body.

5. INBOUND ROUTING FOR TEAM@VCPTRADER.COM
==================================================

When an email is received for:

team@vcptrader.com

perform the following workflow:

1. Verify the webhook.
2. Retrieve the complete received email from Resend.
3. Normalize sender and recipient addresses.
4. Reject or quarantine obviously malformed, dangerous, or oversized content.
5. Sanitize HTML before displaying it in the admin portal.
6. Store the inbound message in the database.
7. Attempt to match the sender email to an existing VCP Trader AI user.
8. Create a new support ticket or append the message to an existing thread.
9. Forward a safe representation of the inbound email to:
   support@sunfishtrading.com
10. Send an acknowledgment to the sender from:
   VCP Trader AI <team@vcptrader.com>
11. Preserve threading identifiers where possible.
12. Record all actions in an auditable email event log.

Do not create forwarding loops.

Before forwarding, explicitly block forwarding when the sender or return path is:

- team@vcptrader.com
- support@sunfishtrading.com
- another known automated forwarding address that would cause recursion

Add an internal forwarding marker header such as:

X-VCP-Forwarded: true

Do not forward a message again if that marker already exists.
