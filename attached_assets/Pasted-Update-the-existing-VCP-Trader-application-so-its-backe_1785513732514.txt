Update the existing VCP Trader application so its backend can communicate with the already-deployed `vcp-trader-mcp` service over authenticated Streamable HTTP MCP.

Important context:

- VCP Trader is an existing production application built in Replit and deployed on Railway.
- `vcp-trader-mcp` is a separate Railway service in the same overall VCP Trader environment.
- The MCP server is already built, deployed, healthy, and verified end-to-end over HTTP.
- Current MCP tools are:

  get_quote
  get_market_history
  get_news
  scan_vcp
  get_positions

- The MCP endpoint is:

  /mcp

- The health endpoint is:

  /health

- MCP HTTP auth uses:

  Authorization: Bearer <MCP_SERVICE_TOKEN>

- The MCP server uses the current Model Context Protocol SDK with Streamable HTTP and stateful sessions.
- Do not rebuild or modify the MCP server in this task.
- Do not add direct browser-to-MCP communication.
- Do not add autonomous trading.
- Do not change the existing InstaTrade execution boundary.

Primary goal:

Make the VCP Trader BACKEND an MCP client, then wire the existing AI/chat capability so a user request such as:

"Analyze MU"

can use MCP tools like:

get_quote("MU")
scan_vcp(["MU"])

and synthesize the results into the existing VCP Trader AI response.

Do not replace the current AI architecture blindly. Inspect the existing code first and integrate MCP into the current design.

Use the current official Model Context Protocol TypeScript/JavaScript SDK compatible with the existing application runtime.

--------------------------------------------------
4. CREATE A REUSABLE MCP CLIENT LAYER
--------------------------------------------------

Create a small backend-only module such as:

server/mcp/
  client.ts
  tools.ts
  schemas.ts
  errors.ts

or place it wherever best fits the existing project architecture.

The MCP client should:

- connect lazily
- authenticate with Bearer token
- initialize the MCP session
- discover tools
- reuse the connection/session where safe
- reconnect automatically if the session becomes invalid
- use configurable timeouts
- avoid crashing the VCP Trader server if MCP is unavailable
- normalize MCP errors
- never leak auth credentials

Conceptual interface:

class McpToolsClient {
  connect()
  disconnect()
  listTools()
  callTool(name, args)
}

Then expose typed wrappers such as:

getQuote(symbol)
getMarketHistory(symbol, interval, outputSize)
getNews(symbol, limit)
scanVcp(symbols, lookbackDays)
getPositions(...)

The rest of VCP Trader should not need to know MCP protocol details.

--------------------------------------------------
5. ADD A TOOL ALLOWLIST
--------------------------------------------------

Do not dynamically allow every tool returned by MCP.

Add an explicit backend allowlist:

get_quote
get_market_history
get_news
scan_vcp
get_positions

If the MCP server later exposes new tools, VCP Trader must not automatically allow them without a code/config review.

Reject unknown tools.

--------------------------------------------------
6. MCP CAPABILITY BOUNDARIES
--------------------------------------------------

Treat current MCP tools as read-only.

Support conceptually:

market:read
research:read
scanner:read
portfolio:read

Do NOT support:

trade:execute

Do not create order-placement MCP flows.

Do not allow the AI to bypass InstaTrade.

The existing rule remains:

AI may research and analyze automatically.

Actual trading remains user-directed through the approved VCP Trader execution flow.

--------------------------------------------------
7. USER CONTEXT SECURITY
--------------------------------------------------

Be careful with get_positions.

Do NOT let the LLM invent arbitrary account IDs.

The backend must derive user/account context from the authenticated VCP Trader session.

If account context is not yet safely supported by the MCP server integration, leave get_positions disabled from AI use for the first production release while still keeping the typed wrapper available.

For Phase 1 VCP integration, prioritize:

get_quote
get_market_history
get_news
scan_vcp

Portfolio access can be enabled after authenticated account context is verified end-to-end.

9. AI SYSTEM RULES

Add rules to the current AI system prompt or orchestration instructions.

11. TOOL RESPONSE HANDLING
--------------------------------------------------

Preserve structured values as long as possible.

}

Do not show raw MCP protocol errors to users unless useful.

--------------------------------------------------
12. CONNECTION MANAGEMENT
--------------------------------------------------

The MCP server uses stateful Streamable HTTP sessions.

Implement robust client lifecycle behavior.

The VCP backend should:

- lazily connect
- reuse an active MCP client/session when safe
- reconnect after session expiration or connection failure
- avoid reconnect storms
- close cleanly on backend shutdown
- tolerate temporary MCP service restarts during Railway deploys

Use a small retry strategy with bounded backoff.

Do not infinitely retry requests.
