==================================================
3. GENERIC MULTI-STRATEGY FLOW
==================================================

For generic analysis:

1. Extract one ticker using the existing safe ticker extraction.

2. Retrieve the authoritative strategy registry.

3. Select only strategies where:
   - enabled = true
   - targetedScan = true
   - requested/default timeframe is supported

4. Call scan_strategy once per eligible strategy.

Use bounded concurrency.

Do not make uncontrolled parallel calls.

Use an appropriate concurrency limit such as 3–4.

5. Treat these as valid outcomes:
   - setup returned
   - setup:null
   - unsupported/no result
   - one strategy failure while others succeed

One strategy failure must not fail the entire analysis.

6. Preserve every returned SetupCandidate independently.

Do not collapse multiple strategies for the same symbol.

7. Do not compare raw strategy scores unless the system explicitly provides normalized ranking.

8. Determine the strongest setup using deterministic evidence in this order:

   a. qualified result from rank_trade_candidates, if available
   b. actionable status: triggered/ready before forming
   c. valid trigger present
   d. freshness
   e. market-regime compatibility
   f. candidate qualification
   g. source/production ranking
   h. raw score only within the same strategy family when valid

9. Run build_trade_candidate for:
   - the strongest actionable setup
   - optionally the next one or two setups for comparison
   - never more than a safe bounded maximum

10. Produce a structured multiStrategyAnalysis response.

==================================================
5. OVERALL VERDICT RULES
==================================================

Use deterministic rules.

TRADE_CANDIDATE:
At least one setup is qualified by build_trade_candidate as:
- STOCK
- LIVE_OPTIONS
- ESTIMATED_OPTIONS

WATCH:
No qualified trade exists, but at least one fresh setup is ready, triggered or forming with meaningful evidence.

NO_TRADE:
Setups were evaluated, but all were explicitly rejected.

INSUFFICIENT_DATA:
No usable strategy or market context could be obtained.

Do not allow the LLM to override these verdicts.

==================================================
9. AI NARRATIVE RULES
==================================================

The model receives the structured result and may explain it.

It must:

- name the primary strategy
- distinguish primary and supporting evidence
- state the deterministic verdict
- explain why a trade qualifies or fails
- mention important earnings/market/risk warnings
- avoid presenting scanner detections as recommendations
- never invent missing trigger or levels
- never compare raw scores as if universally equivalent
- never contradict TradeCandidate/NO_TRADE

==================================================
10. PERFORMANCE AND RESILIENCE
==================================================

- Cache authoritative strategy metadata.
- Use bounded parallel scan_strategy calls.
- Apply per-tool timeout.
- Permit partial success.
- Do not rerun full-market scan_opportunities for a single-symbol analysis.
- Do not call strategies that do not support targeted scans.
- Avoid duplicate quote/history calls.
- Cap the number of candidate-enrichment calls.

==================================================
11. CONFIDENCE
==================================================

Server-derived confidence should reflect:

- number of successful strategy scans
- market-data completeness
- setup freshness
- candidate-engine success
- consistency of evidence

Do not use high confidence when:

- most strategies failed
- market data is unavailable
- results are mock/synthetic
- freshness is unknown or stale
- primary setup is ambiguous

Bearish or NO_TRADE does not automatically mean low confidence.
