VCP TRADER AI — SPRINT 2.8.7 ARCHITECTURE AUDIT B
Execution Preflight Independent Layer vs Broker Layer

STATUS

Audit A is complete.

25 broker gate sites were found.

Critical findings include:

- ExecutionPreflightPanel disabled when !brokerConnected
- Trade Plan detail preflight query enabled only when brokerConnected
- determineOverallStatus() returns UNAVAILABLE when broker is absent
- several independent dimensions are hidden/masked
- broker absence is currently treated as a failure even when only execution-specific
  capabilities are unavailable

DO NOT IMPLEMENT CODE IN THIS TASK.

This is a design/audit task only.

============================================================
OBJECTIVE
============================================================

Redesign the 12-dimension Execution Preflight architecture into two explicit
layers:

A. TRADE PLAN READINESS / INDEPENDENT PREFLIGHT

B. BROKER EXECUTION READINESS

The goal is:

A user WITHOUT a brokerage connection should still be able to run meaningful
preflight checks on a saved Trade Plan.

Broker absence must NOT cause broker-independent planning/readiness dimensions
to disappear or be reported as platform failure.

However:

Broker-independent readiness must NEVER authorize broker submission.

Actual broker submission must still require every broker/execution-specific
safety gate.

3. DEFINE TWO LAYERS
============================================================

Design canonical layer names.

Preferred conceptual direction:

TRADE_PLAN_READINESS

and

BROKER_EXECUTION_READINESS

But inspect existing naming conventions before locking terms.

TRADE PLAN READINESS should answer:

"Is this saved research/planning artifact internally ready and current?"

BROKER EXECUTION READINESS should answer:

"Can this specific plan be prepared for execution using the connected
broker/account right now?"

These are different questions and must not share one ambiguous overall result.
